# THRIVE University Admin

هذه النسخة هي **THRIVE Test**. إعدادات التشغيل الحالية في [تقرير العزل](../../docs/TEST_ISOLATION.ar.md).

لوحة Angular مرتبطة بالـAPI: مؤشرات مجمعة، إدارة الخدمات والمحتوى، ومتابعة حالة الإحالات. التوكن والجلسة في الذاكرة فقط، والخادم يفرض الدور ونطاق الجامعة لكل عملية.

## التشغيل المحلي

من هذا المجلد، باستخدام Node.js متوافق مع Angular22 وnpm:

```powershell
. ../../scripts/lib/GeneratedWorkspace.ps1
Initialize-ThriveTestGeneratedWorkspace (Resolve-Path ../..).Path -Component Admin
npm ci
npm start -- --host localhost --port 4300
```

الدخول التجريبي معطل في development الافتراضي وproduction. تفعيله الصريح:

```powershell
npm run start:demo -- --host localhost --port 4300
```

يتطلب Backend على http://localhost:5280 في Development مع DevelopmentIdentity:Enabled=true، وقاعدة بيانات محدثة بـmigrations. proxy.conf.json يمرر /api للخادم. جلسة التطوير تستخدم persona=admin وتتحقق من role=UniversityAdmin عبر /me.

الدخول الجامعي الحقيقي ينتظر إعداد مزود الهوية. الخدمات والبيانات الاصطناعية موسومة. بيئة demo لا تمثل خدمة طلابية أو طوارئ فعلية. لا تحفظ توكن في localStorage أو cookies.

## الوظائف

- Dashboard يقرأ تقارير API؛ null يظهر كحجب خصوصية مع الحد الأدنى المعتمد للمجموعة، وليس صفرًا.
- الخدمات: قائمة وإضافة وتعديل وتفعيل/تعطيل، مستوى دعم ومعلومات وصول. التحقق المؤسسي يحتاج مسار مراجعة معتمد، وحقل verified للعرض فقط حاليًا.
- الموارد: قائمة وإضافة وتعديل، مسودة/نشر، عربية وإنجليزية، مصدر وتصنيف وإصدار. النشر لا يعني مراجعة سريرية؛ isDemo وبيانات المراجع حقول يملكها الخادم.
- الإحالات: قائمة دون معرفات الطلاب أو نتائجهم، وانتقالات الحالة المسموحة فقط. لا يتحول الفشل أو409 إلى نجاح.
- عربية RTL وإنجليزية LTR، واجهة متجاوبة، وتحميل وأخطاء وحالات فارغة.

لا يرسل التطبيق بريدًا أو إشعارات ولا يحجز مواعيد عبر تقويم خارجي. تحديث Scheduled إجراء تشغيلي لمستخدم مخول.

## البناء والتحقق

```powershell
npm run build
npm test
npm run format:check
```

البناء الافتراضي يغلق زر التطوير. npm run build:demo لنسخة فحص محلية. الناتج dist/thrive-university-admin/browser؛ الاستضافة المستقبلية تعيد مسارات الواجهة إلى index.html وتوفر API من أصل موثوق.

نجح البناء الإنتاجي و11 اختبارًا سلوكية: بوابة الدخول، دور الإدارة، إزالة التوكن عند الخروج و401، التعارض، إخفاء العمليات قبل الدخول، حجب المؤشرات، اللغة، الحقول المطلوبة، وانتقالات الإحالة. الفحص الحي مع PostgreSQL جزء من التحقق الكامل للمشروع.

## التنظيم

```text
src/app/
  core/api/              عقود typed وHTTP وجلسة بالذاكرة
  core/i18n/             نصوص اللغتين وحالة اللغة
  shared/request-state/  دورة التحميل والخطأ والملاحظات المشتركة
  features/dashboard/    التقرير المجمع
  features/services/     قائمة الخدمات ونموذجها
  features/resources/    المحتوى والنشر
  features/referrals/    متابعة الإحالات
src/environments/        إعداد افتراضي مغلق وdemo صريح
```

أخطاء API تحمل نوعًا منضبطًا دون طباعة جسم الاستجابة. عقد العمليات في ../../contracts/IMPLEMENTATION_SLICE.md.

## التحقق الحي

نجح فحص المتصفح مع API وPostgreSQL فعليتين في بيئة التطوير: دخول الإدارة، إضافة خدمة وتعديلها، إضافة مورد ونشره وتحديث إصداره، ظهور التعديلات في دليل الطالب، إنشاء إحالة من الطالب ثم تحديثها من الإدارة عبر Requested → Received → Scheduled → Completed، ورؤية الطالب للحالة النهائية. جرى كذلك فحص تسجيل الخروج واللغتين وشاشة390px وعدم وجود أخطاء JavaScript أو توكن في تخزين المتصفح. جميع السجلات المنشأة للاختبار اصطناعية وموسومة isDemo.
